# Alcogames

Простой сайт-каталог алкогольных игр для вечеринок: список игр с сортировкой, фильтром по количеству
игроков, выбором случайной игры и лайками — без регистрации. Плюс лёгкая админка (по общему секретному
токену, без полноценной авторизации) для добавления/редактирования/удаления игр, в том числе через
автоматический разбор произвольного текста с помощью LLM (DeepSeek или Yandex Cloud, провайдер
выбирается в админке).

## Стек

- Backend: Python + FastAPI, хранение данных в одном JSON-файле (без БД).
- Frontend: обычные HTML/CSS/JS без сборки и фреймворков. Дизайн всех страниц, включая админку — «Bare Metal»
  (серый лист, тиснёный Tahoma, зелёный терминал для всего «машинного»), портирован из проекта Claude Design
  в `frontend/css/bare-metal.css`; шапка и футер как на kanstancin.net. Светлая тема по умолчанию следует
  системной, кнопка `theme` в шапке переключает. Моноширинный шрифт — IBM 3270 (rbanffy,
  https://github.com/rbanffy/3270font, OFL), лежит в `frontend/fonts/`, внешних запросов за шрифтами нет.
- Один Docker-контейнер отдаёт и API, и статику фронтенда.

## Быстрый старт

```bash
cp .env.example .env
# отредактируйте .env: задайте ADMIN_TOKEN (любая длинная случайная строка).
# LLM-провайдер и ключи настраиваются потом в админке (раздел «Настройки LLM»).

docker compose up -d --build
```

Открыть `http://localhost:8000/` — список игр (пустой при первом запуске).
Админка: `http://localhost:8000/admin.html` — при первом заходе ввести значение `ADMIN_TOKEN` из `.env`
(токен сохраняется в localStorage браузера, повторно вводить не нужно).

## Где хранятся данные

Все игры лежат в `./data/games.json` на хосте (примонтировано в контейнер как volume). Файл:

- переживает пересборку и перезапуск образа;
- можно редактировать вручную (это обычный JSON-массив);
- не требует пересборки образа при изменении — правки в `data/` подхватываются сразу, без `docker compose build`.

Аналогично секреты (`ADMIN_TOKEN`, ключи LLM по умолчанию) читаются из `.env` в рантайме и никогда не
запекаются в образ — их тоже можно менять без пересборки (достаточно `docker compose up -d` для
перезапуска с новым `.env`). Настройки LLM, сделанные в админке, лежат рядом в `./data/llm_settings.json`
(файл с правами `0600`, в git не попадает).

## Добавление игр

Два способа, оба в `/admin.html`, через одну и ту же форму:

1. **Вручную** — заполнить поля формы (название, мин/макс количество игроков, описание, источник) и
   нажать «Сохранить».
2. **Через LLM** — вставить в текстовое поле произвольное, неструктурированное описание игры, нажать
   «Распарсить через LLM». Модель выбранного провайдера разложит текст на поля формы. **Результат не
   сохраняется автоматически** — это только предзаполнение формы, его нужно проверить (и при
   необходимости поправить) и затем явно нажать «Сохранить».

Если провайдер не настроен, кнопка «Распарсить через LLM» отключена с подсказкой, а `POST /api/admin/parse`
возвращает 503 — ручное добавление/редактирование игр при этом продолжает работать как обычно.

## Настройки LLM

Раздел «Настройки LLM» в `/admin.html`: провайдер (выключено / DeepSeek / Yandex Cloud), ключи, базовый
URL и модель DeepSeek, идентификатор каталога и модель Yandex. Кнопка «Проверить» делает реальный
короткий запрос к провайдеру и показывает ошибку словами (`auth`, `quota`, `network`, `bad_response`).

- Сохраняется в `data/llm_settings.json` (только переопределения; права `0600`). В ответах API ключи не
  возвращаются — только последние 4 символа. Пустое поле ключа в форме оставляет сохранённый ключ,
  чекбокс «Очистить» удаляет его.
- Переменные `LLM_PROVIDER`, `DEEPSEEK_*`, `YANDEX_*` в `.env` — **только значения по умолчанию**;
  то, что сохранено в админке, важнее. Если `LLM_PROVIDER` не задан, но есть `DEEPSEEK_API_KEY`,
  провайдером по умолчанию считается DeepSeek (совместимость со старыми установками).
- **Yandex Cloud**: сервисному аккаунту нужна роль `ai.languageModels.user`, API-ключу — область
  `yc.ai.languageModels.execute`, идентификатор каталога вида `b1g…`. Запросы идут в Text Generation
  API (`https://llm.api.cloud.yandex.net/foundationModels/v1/completion`) с `modelUri`
  `gpt://<каталог>/<модель>`; модель по умолчанию `yandexgpt-lite/latest` (≈ $0.0016 за 1000 токенов),
  для более аккуратного переноса длинных правил можно указать `yandexgpt/latest` (Pro). Ответ
  запрашивается в режиме `jsonObject`, лимит `maxTokens` 4000.
- **DeepSeek**: OpenAI-совместимый `chat/completions` с `response_format: json_object`.

Новый провайдер: класс с `name`, `model`, `async parse(text) -> ParsedGameFields` и `async check() -> str`
в `backend/app/llm_providers.py`, ветка в `llm_settings.get_provider()`, поле в `LLMSettings`, пункт в
выпадающем списке админки.

Количество игроков хранится как `min_players` / `max_players` (без верхней границы — отметить чекбокс
«Без верхней границы»); строка вида «3–6», «4+» или «любое» вычисляется на лету, не хранится.

Помимо правил (`description`) у игры есть метаданные для списка: `summary` (одно предложение),
`minutes` (примерное время), `tags` (1–3 тега из закрытого словаря в `llm_providers.TAGS`: «карты»,
«кубики», «разговорная», «активная», «команды», «роли», «быстрая», «долгая» и т.д.) и `props` (что нужно).
Все они необязательны: LLM заполняет их при разборе текста, а для уже сохранённых игр — кнопка
«Дозаполнить теги и время у игр без них» в админке (обрабатывает игры без этих полей по одной) или кнопка
«LLM» в строке таблицы (одна игра заново). Правила при дозаполнении не меняются. Неизвестные теги
отбрасываются, чтобы каталог оставался однородным.

Главная страница: быстрый выбор числа игроков, сортировка, случайная игра, список строк «название —
краткое описание — игроки / время / лайки»; клик открывает диалог с правилами, реквизитом, тегами и лайком.
Ссылка `?game=<id>` открывает диалог сразу, `game.html?id=<id>` — та же карточка отдельной страницей.

## Развёртывание за reverse proxy на поддиректории домена

Приложение написано так, чтобы одинаково работать и на корне домена (`example.com/`), и на
поддиректории (`example.com/alcogames/`) — весь фронтенд использует **относительные** пути к
статике и API (без ведущего `/`). Рекомендуемая схема — nginx срезает префикс перед проксированием,
и бэкенду вообще не нужно знать о существовании этого префикса:

```nginx
location /alcogames/ {
    proxy_pass http://alcogames:8000/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

**Важно:** URL должен открываться с завершающим слэшем — `https://example.com/alcogames/`, а не
`https://example.com/alcogames`. Из-за относительных путей во фронтенде без слэша браузер резолвит
`api/games`, `js/main.js` и т.п. на директорию выше домена, и всё ломается. Рекомендуется настроить в
nginx редирект с версии без слэша на версию со слэшом.

## Запуск без Docker (для разработки)

```bash
cd backend
pip install -r requirements.txt
export ADMIN_TOKEN=dev-token
export DATA_DIR=../data
uvicorn app.main:app --reload
```

## Тесты

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```

Провайдеры тестируются через `httpx.MockTransport` без обращения к внешним API.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `ADMIN_TOKEN` | да | – | Секретный токен для доступа к `/api/admin/*`; без него приложение не запустится |
| `LLM_PROVIDER` | нет | `deepseek`, если задан `DEEPSEEK_API_KEY`, иначе `none` | Провайдер LLM по умолчанию: `none`, `deepseek`, `yandex` (переопределяется в админке) |
| `DEEPSEEK_API_KEY` | нет | – | Ключ DeepSeek API по умолчанию |
| `DEEPSEEK_BASE_URL` | нет | `https://api.deepseek.com` | Базовый URL DeepSeek API |
| `DEEPSEEK_MODEL` | нет | `deepseek-chat` | Модель DeepSeek для разбора текста |
| `YANDEX_API_KEY` | нет | – | API-ключ сервисного аккаунта Yandex Cloud по умолчанию |
| `YANDEX_FOLDER_ID` | нет | – | Идентификатор каталога Yandex Cloud (`b1g…`) |
| `YANDEX_MODEL` | нет | `yandexgpt-lite/latest` | Модель YandexGPT (часть `gpt://<каталог>/<модель>`) |
| `DATA_DIR` | нет | `./data` | Каталог с `games.json` и `llm_settings.json` |

## API

| Метод | Путь | Auth | Описание |
|---|---|---|---|
| GET | `/api/games` | – | Список всех игр |
| POST | `/api/games/{id}/like` | – | Лайк (один на игру на браузер, через куку `liked_games`) |
| GET | `/api/health` | – | Healthcheck |
| POST | `/api/admin/games` | `X-Admin-Token` | Создать игру |
| PUT | `/api/admin/games/{id}` | `X-Admin-Token` | Изменить игру |
| DELETE | `/api/admin/games/{id}` | `X-Admin-Token` | Удалить игру |
| POST | `/api/admin/parse` | `X-Admin-Token` | Разобрать произвольный текст через LLM (только превью, не сохраняет) |
| POST | `/api/admin/games/{id}/enrich` | `X-Admin-Token` | Дозаполнить `summary`, `minutes`, `tags`, `props` через LLM и сохранить |
| GET | `/api/admin/llm-settings` | `X-Admin-Token` | Текущие настройки LLM (ключи замаскированы) |
| PUT | `/api/admin/llm-settings` | `X-Admin-Token` | Изменить настройки LLM (частичное обновление, `clear_*` очищает ключ) |
| POST | `/api/admin/llm-settings/test` | `X-Admin-Token` | Проверить провайдера реальным коротким запросом |

## Известные ограничения

- Хранилище — один JSON-файл с блокировкой на процесс; рассчитано на ≤100 игр и низкую нагрузку.
- Контейнер должен работать с **одним uvicorn-воркером** (`--workers 1`, уже задано в `Dockerfile`).
  Несколько воркеров/процессов не координируют блокировку файла между собой и могут повредить
  `games.json` — не увеличивайте `--workers`.
- Лайки дедуплицируются только по куке браузера, не по реальному пользователю — это осознанный
  компромисс ради простоты (снятие лайка не предусмотрено).
- Админка защищена общим секретным токеном, а не полноценной системой регистрации/авторизации —
  подходит для доверенного круга людей, не для публичной многопользовательской модерации.
